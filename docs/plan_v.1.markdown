## 1. 나의 프로젝트 목표

### 1.1 한 줄 소개

특수 동물 보호자가 동물 종류와 지역에 따라 전문 동물병원을 검색하고, 사용자들이 병원 정보와 실제 방문 후기를 공유할 수 있는 웹 서비스.

### 1.2 누구를 위한 것인가

- 새, 햄스터, 고슴도치, 토끼, 파충류 등 특수 동물을 키우는 보호자
- 특수 동물 진료가 가능한 병원을 찾는 사람
- 자신의 병원 진료 정보를 알리고 싶은 동물병원 관계자
- 실제 방문 경험과 병원 정보를 다른 보호자와 공유하고 싶은 사용자

### 1.3 핵심 기능 3가지

1. **특수 동물 병원 검색 및 필터링**
   - 지역별 검색
   - 동물 종류별 검색
   - 진료 항목별 검색
   - 여러 조건을 조합한 검색

2. **병원 정보 등록 및 상세 정보 조회**
   - 병원명, 주소, 연락처, 진료 가능한 동물 및 진료 항목 조회
   - 로그인 사용자의 신규 병원 등록
   - 병원 정보의 최초 등록자와 등록일 표시
   - 병원 정보 확인 상태 표시

3. **등록자 정보, 댓글 및 방문 후기 공유**
   - 병원 정보 등록자 표시
   - 일반 사용자와 확인된 병원 관계자 구분
   - 병원별 댓글 작성 및 조회
   - 방문 날짜, 방문 동물, 실제 진료 여부 등을 포함한 방문 후기 작성 및 조회

### 1.4 완성의 기준

최종 제출 시점에 다음 기준을 충족하는 것을 목표로 한다.

- 병원 데이터 15개 이상을 등록한다.
- 병원 목록 및 상세 정보를 조회할 수 있다.
- 지역·동물 종류·진료 항목을 각각 검색할 수 있고, 여러 조건을 조합할 수 있다.
- 회원가입, 로그인, 로그아웃이 정상 작동한다.
- 로그인한 사용자가 새로운 병원 정보를 등록할 수 있다.
- 새로 등록된 병원은 목록에 즉시 반영되고 기본 상태가 `미확인`으로 표시된다.
- 병원 상세 화면에서 최초 등록자, 등록일, 등록자 유형 및 정보 확인 상태를 확인할 수 있다.
- 병원별 댓글과 방문 후기를 작성하고 조회할 수 있다.
- 작성자는 본인이 작성한 댓글과 후기를 수정하거나 삭제할 수 있다.
- 최소 3명의 테스트 사용자에게 주요 기능을 사용하게 하고 기본 사용 흐름을 검증한다.
- 실제로 확인한 정보와 설명·시연을 위한 예시 데이터를 명확하게 구분한다.
- PC와 모바일에서 주요 화면을 이용할 수 있다.

## 2. 프로젝트 개요 및 추진 배경

### 2.1 프로젝트 개요

특수 동물 보호자가 동물의 종류, 지역, 진료 항목에 따라 진료 가능한 동물병원을 찾고, 병원 정보를 확인하거나 새로운 정보를 등록하고, 다른 사용자의 댓글과 실제 방문 후기를 참고할 수 있는 웹 서비스다.

### 2.2 해결하려는 문제

특수 동물은 종류에 따라 진료할 수 있는 병원이 제한적일 수 있다. 보호자는 가까운 동물병원을 찾더라도 자신이 키우는 동물을 실제로 진료하는지, 원하는 진료 항목을 제공하는지 별도로 확인해야 할 수 있다.

이 프로젝트는 다음 문제를 줄이는 것을 목표로 한다.

- 특정 동물을 진료하는 병원을 찾기 어렵다.
- 병원별 진료 가능 동물과 진료 항목을 한곳에서 비교하기 어렵다.
- 병원 정보가 누가 언제 등록했는지 알기 어렵다.
- 병원 정보가 실제와 다르거나 오래되었는지 판단하기 어렵다.
- 다른 보호자의 실제 방문 경험을 확인하기 어렵다.

### 2.3 서비스의 핵심 가치

- **접근성:** 특수 동물 진료 병원을 조건에 맞게 찾을 수 있다.
- **편의성:** 병원별 기본 정보와 진료 정보를 한곳에서 확인할 수 있다.
- **정보 신뢰성:** 등록자, 등록일, 정보 확인 상태, 실제 방문 경험을 함께 제공한다.

## 3. 주요 기능 및 운영 정책

### 3.1 병원 검색 및 필터링

검색 조건은 다음과 같다.

- 지역
- 진료 가능한 동물 종류
- 진료 항목
- 복수 조건 조합

검색 결과에는 병원명, 지역, 진료 가능한 동물, 주요 진료 항목, 정보 확인 상태를 표시한다. 검색 결과가 없을 때는 안내 문구를 제공하고, 사용자가 검색 조건을 초기화할 수 있도록 한다.

### 3.2 병원 정보 등록 및 상세 조회

병원 정보의 기본 항목은 다음과 같다.

- 병원명
- 주소 및 지역
- 연락처
- 진료 가능한 동물
- 진료 항목
- 병원 소개
- 정보 출처 또는 참고 사항(확보 가능한 경우)

로그인한 사용자는 신규 병원 정보를 등록할 수 있다. 등록된 정보는 목록에 즉시 반영하되, 기본 확인 상태는 `미확인`으로 설정한다.

### 3.3 정보 확인 상태

병원 정보의 확인 상태와 등록자 유형은 서로 다른 정보로 관리한다.

| 상태 | 의미 |
|---|---|
| 미확인 | 사용자에 의해 등록되었으나 아직 확인 절차가 완료되지 않은 정보 |
| 확인됨 | 신뢰할 수 있는 출처나 확인 절차를 통해 확인된 정보 |
| 확인 필요 | 정보가 오래되었거나 변경 제보 등으로 재확인이 필요한 정보 |

- 실제로 확인하지 않은 병원을 `확인됨`으로 표시하지 않는다.
- 미확인 병원도 목록에 노출할 수 있지만 확인된 병원과 시각적으로 구분한다.
- 미확인 정보가 현재 진료 가능 여부를 보증하지 않는다는 안내를 제공한다.
- 정보 확인 상태는 병원 관계자 인증 여부와 별도로 관리한다.

### 3.4 등록자 유형

| 유형 | 표시 및 의미 |
|---|---|
| 일반 회원 | 개인적으로 병원 정보를 등록하거나 의견을 공유하는 사용자 |
| 병원 관계자 인증 | 해당 병원과의 관계를 확인받은 사용자 |
| 병원 공식 계정 | 병원이 공식적으로 관리하는 계정 |

초기 버전에서는 일반 회원과 관리자가 관계를 확인한 병원 관계자를 구분하는 수준으로 구현한다. 자기소개에 수의사·병원장이라고 적었다는 이유만으로 인증 배지를 부여하지 않는다. 병원 관계자 인증이 병원에 관한 모든 정보의 정확성을 보증하는 것도 아니다.

### 3.5 댓글 및 방문 후기

댓글과 방문 후기는 목적을 구분한다.

| 구분 | 댓글 | 방문 후기 |
|---|---|---|
| 목적 | 질문, 답변, 자유로운 의견 교환 | 실제 방문 및 진료 경험 공유 |
| 작성자 | 로그인 사용자 | 로그인 사용자 |
| 주요 내용 | 질문, 답변, 의견 | 방문 날짜, 방문 동물, 실제 진료 여부, 경험 |
| 관리 | 작성자 본인 수정·삭제 | 작성자 본인 수정·삭제 |

방문 후기에는 다음 항목을 포함한다.

- 방문한 동물 종류
- 방문 날짜
- 실제 진료 여부
- 병원 서비스 및 진료 경험
- 상세 후기

후기는 개인의 경험이며 병원의 현재 진료 가능 여부를 보증하지 않는다는 안내를 제공한다. 허위 후기, 악의적 평가, 오래된 정보, 개인정보 노출 가능성을 고려한다. 신고 및 분쟁 처리 기능은 초기 필수 범위에서 제외하고 추후 개선 요소로 남긴다.

### 3.6 사용자 권한

- 비로그인 사용자: 병원 검색 및 정보 조회
- 로그인 사용자: 병원 신규 등록, 댓글 및 방문 후기 작성
- 작성자 본인: 본인이 작성한 댓글 및 방문 후기 수정·삭제
- 관리자: 초기 버전에서 필요한 범위의 병원 정보 확인 상태 및 병원 관계자 인증 상태 관리

화면에서만 권한을 검사하지 않고, 서버에서도 인증 및 작성 권한을 확인한다.

## 4. 제출 단계별 개발 범위

각 제출 단계는 이전 단계의 기능을 유지하면서 다음 기능을 추가하는 방식으로 진행한다.

### 4.1 1차 제출 — 병원 정보 목록 구축

**목표:** 사용자가 특수 동물 병원 목록과 기본 정보를 조회할 수 있는 서비스를 만든다.

구현 범위:

- 메인 화면 및 서비스 소개
- 병원 목록 조회
- 병원 상세 정보 조회
- 동물 종류 분류
- 진료 항목 분류
- 초기 병원 데이터 등록
- 기본 반응형 화면

병원 데이터는 15개 이상을 목표로 한다. 실제 병원 정보는 출처와 확인 가능한 내용을 기록하고, 시연을 위한 예시 데이터는 예시 데이터임을 명시한다.

**완료 기준:**

- 병원 목록이 정상적으로 출력된다.
- 병원을 선택하면 상세 정보가 표시된다.
- 새로고침 후에도 데이터가 유지된다.
- PC와 모바일에서 기본 화면이 정상적으로 표시된다.

### 4.2 2차 제출 — 검색 및 필터링

**목표:** 사용자가 원하는 조건에 맞는 병원을 빠르게 찾을 수 있도록 한다.

구현 범위:

- 지역별 검색
- 동물 종류별 검색
- 진료 항목별 검색
- 복수 조건 조합 검색
- 검색 결과에 병원명, 지역, 진료 동물, 주요 진료 항목, 확인 상태 표시
- 검색 조건 초기화
- 검색 결과 없음 안내

**완료 기준:**

- 지역·동물 종류·진료 항목을 각각 검색할 수 있다.
- 여러 검색 조건을 동시에 적용할 수 있다.
- 조건에 맞는 결과가 갱신된다.
- 검색 결과가 없을 때 안내가 표시된다.
- 검색 조건을 초기화할 수 있다.

### 4.3 최종 제출 — 사용자 참여형 플랫폼

**목표:** 사용자가 병원 정보를 직접 등록하고, 등록자 정보와 실제 방문 경험을 공유할 수 있도록 한다.

#### A. 회원가입 및 로그인

- 이메일 및 비밀번호 기반 회원가입
- 로그인 및 로그아웃
- 닉네임 설정
- 사용자 프로필 조회
- 일반 사용자와 병원 관계자 구분

#### B. 병원 신규 등록

- 로그인한 사용자가 병원 등록 페이지에서 정보 입력
- 병원명, 주소 및 지역, 연락처, 진료 가능한 동물, 진료 항목, 병원 소개, 출처 또는 참고 사항 입력
- 등록 즉시 병원 목록에 반영
- 신규 등록 병원의 기본 확인 상태는 `미확인`
- 등록자 계정 및 최초 등록 날짜 저장
- 기본적인 중복 등록 검사 고려

#### C. 등록자 정보 표시

병원 상세 페이지에 다음 정보를 표시한다.

- 최초 등록자 닉네임 및 등록일
- 등록자 유형
- 정보 확인 상태
- 수정 이력이 존재하면 최근 수정자 및 수정일

최초 등록자 정보와 이후 수정 이력은 구분해 보존한다.

#### D. 댓글 및 방문 후기

- 병원별 댓글 작성 및 조회
- 병원별 방문 후기 작성 및 조회
- 방문 동물, 방문 날짜, 실제 진료 여부, 서비스 경험 및 상세 후기 입력
- 작성자 본인의 댓글·후기 수정 및 삭제

**완료 기준:**

- 회원가입, 로그인 및 로그아웃이 정상 작동한다.
- 로그인 사용자가 병원을 등록할 수 있다.
- 신규 병원이 즉시 목록에 나타나고 `미확인`으로 표시된다.
- 병원 상세 화면에서 등록자 정보와 확인 상태를 확인할 수 있다.
- 일반 회원과 확인된 병원 관계자를 구분할 수 있다.
- 댓글과 방문 후기를 작성하고 조회할 수 있다.
- 작성자가 본인의 댓글과 후기를 수정하거나 삭제할 수 있다.

| 1일차 | 화면 구성, 데이터베이스 설계, 병원 초기 데이터, 목록 및 상세 화면 | 1차 제출 |
| 2일차 | 지역·동물·진료 항목 검색, 복수 필터, 검색 결과 처리 | 2차 제출 |
| 3일차 | 회원가입·로그인, 병원 등록, 등록자 및 확인 상태 표시 | 최종 제출 핵심 기능 구현 |
| 4일차 | 댓글·방문 후기, 오류 수정, 사용자 테스트, README 및 시연 자료 | 최종 제출 및 검증 |

**일정 전제:** 개발 환경과 데이터베이스가 준비되어 있다는 가정으로 작성했다. 인증이나 데이터베이스를 처음부터 구축해야 하는 경우에는 해당 작업에 걸리는 시간을 고려해 세부 작업의 우선순위를 조정한다. 핵심 기능을 안정적으로 완성하는 것을 기능 수를 늘리는 것보다 우선한다.

## 6. 데이터베이스 설계 초안

최종 제출까지 필요한 기본 테이블은 다음과 같다.

| 테이블 | 역할 및 주요 데이터 |
|---|---|
| `users` | 회원 정보, 닉네임, 계정 유형 |
| `hospitals` | 병원 기본 정보, 주소, 연락처, 확인 상태 |
| `animals` | 동물 종류 분류 |
| `hospital_animals` | 병원별 진료 가능 동물 연결 |
| `treatments` | 진료 항목 분류 |
| `hospital_treatments` | 병원별 진료 항목 연결 |
| `hospital_history` | 병원 최초 등록 및 수정 이력 |
| `reviews` | 방문 후기, 작성자, 방문 날짜, 방문 동물, 진료 경험 |
| `comments` | 병원별 댓글 및 작성자 정보 |

### 6.1 데이터 설계 원칙

1. 병원 정보와 등록자 정보를 분리한다.
2. 정보 확인 상태를 별도 필드로 관리한다.
3. 병원 정보가 수정되어도 최초 등록자와 수정 이력을 보존한다.
4. 동물 종류와 진료 항목은 분류 데이터로 관리한다.
5. 사용자 인증과 작성 권한은 서버에서도 검사한다.
6. 초기 구현에 불필요한 복잡성을 추가하지 않되, 추후 확장 가능성을 고려한다.

## 7. 초기 버전의 범위에서 제외할 기능

다음 기능은 4일 내 핵심 제출 범위에 포함하지 않는다.

- 지도 API 연동 및 지도 기반 검색
- 복잡한 병원 관계자 증빙 자료 업로드 및 인증 절차
- 병원 공식 계정의 독립적인 운영 기능
- 후기 별점 및 좋아요
- 사진 및 파일 첨부
- 고도화된 신고·분쟁 처리
- AI 기반 병원 추천
- 실시간 알림

위 항목은 핵심 제출 기능을 안정적으로 완성한 이후 검토한다.

## 8. 최종 제출 이후의 발전 가능 요소

> **이 절의 항목은 현재 개발 범위나 제출 필수 조건이 아니다.** 최종 제출 이후 사용자 피드백, 기술적 여건, 데이터 확보 상황 등을 고려해 추가할 수 있는 발전 방향이다. 현재 단계에서 구현 완료를 전제로 하지 않는다.

### 8.1 지도 기반 검색

- 병원 위치를 지도에 표시

- 거리 및 길찾기 정보 제공

### 8.2 병원 관계자 인증 및 공식 계정 고도화

- 병원 관계자의 증빙 자료 제출
- 관리자 승인 절차 고도화
- 병원 공식 계정 및 병원 정보 직접 관리 기능

### 8.3 커뮤니티 기능 고도화

- 후기 및 댓글 신고
- 유용한 후기 추천
- 사진 첨부
- 댓글 답변 및 알림

### 8.4 병원 정보 신뢰성 관리 고도화

- 병원 정보 수정 이력 공개
- 정보 최신성 확인 요청
- 운영자의 정보 수정 및 검토 도구
- 진료 가능 동물 및 진료 항목 변경 이력 관리

## 9. 프로젝트 진행 및 품질 관리 원칙

1. 제출 단계마다 이전에 완성한 기능을 유지한다.
2. 최종 제출까지는 핵심 기능의 완성도와 안정성을 우선한다.
3. 실제 확인된 정보와 예시 데이터를 명확히 구분한다.
4. 사용자 제보와 병원 공식 확인 정보를 혼동하지 않는다.
5. 미확인 병원은 확인된 병원과 구분하고, 진료 가능 여부를 보증하지 않는다는 안내를 제공한다.
6. 비로그인 사용자는 검색과 조회가 가능하지만, 병원 등록 및 댓글·후기 작성은 제한한다.
7. 권한 검사는 프런트엔드뿐 아니라 서버에서도 수행한다.
8. 최종 제출 이후 발전 가능 요소는 현재 필수 구현 범위와 구분해 관리한다.
9. 기능이나 계획을 변경할 때는 변경 이유와 근거를 기록한다.
10. 실제 구현 완료 여부와 계획상 목표를 구분해 문서화한다.

- 단순한 오탈자 수정이나 표현 다듬기는 별도 버전으로 만들지 않아도 된다.
- 계획 변경과 실제 구현 완료는 구분해 기록한다.
